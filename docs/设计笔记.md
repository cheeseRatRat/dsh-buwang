# 设计笔记

做的时候记下的几个决定，以及它们为什么是这样。

## 一、为什么是「显式读取」而不是「自动召回」

看过一圈同类插件，主流做法是把召回塞进每一轮：检索 → 挑几条 → 注入。那很有效，但它替用户决定了什么重要。

这个库赌的是另一件事：**用户自己知道什么重要，只是懒得说。** 所以把「说一句」的成本压到最低（七个工具、一句话触发），把「自动」的部分全部砍掉。

代价：记忆不会被偶然想起。
好处：上下文里出现的每一行，都是被同意过的。模型不会突然引用你三个月前喝醉时说的话。

## 二、为什么分三层

矛盾只有一句话：**想记得多，又不想上下文压垮。**

- **同游**是唯一允许全文注入的地方。它必须短——一行一条、一直成立。这里的每一条都值得每轮付钱。
- **近期**按天存，索引里只挂标题和一句话。一天里发生了什么，看标题就想起来了。
- **长期**是巩固后的月小记。几天的事压成一段，细节留在档案区，要的时候按日期取。

三层的边界不是按时间划的，是按「**看一行能不能想起来**」划的。想不起来的，才需要翻正文。

## 三、为什么工坊默认一点痕迹都不留

大部分「技能」类功能会常驻一段目录，让模型知道「我有这些能力」。这有代价：目录也是 token，而且会诱导模型在不该用的时候用。

所以这里的默认是：**不启用 = 不存在。** 连名字都不在。

要用的路径是：用户说「搜工坊」→ 列目录 → 用户挑 → 开 → 办完关。人挑，不是模型挑。

## 四、为什么人格只能启用一个

可以有很多个自己，但同一时间只有一个醒着。

如果允许多个同时启用，注入的就不止是长度问题，而是**身份冲突**：两个声音都在说「我是谁」，模型会开始平均它们。

所以「启用」是排他的，存在 `设置.json` 的 `activePersona` 里。想换，就是换一个人。

## 五、为什么删掉的人格进封存而不是真删

人格不只是那段文字。它背后是一整套档案：记忆、工坊、自述。

删一个人格，等于删掉几百天的日子。所以这里做的是**整盒搬进封存**——可以随时「接回来」，三块各自归位；重名就整单拒绝，不做半吊子迁移。

真正的删除留给用户自己：封存页每一行都有「文件夹」按钮，直接开资源管理器，想清就清。

## 六、为什么库的位置由库外的指针决定

「这个库在哪个文件夹」这句话，不能存在库里——那是个鸡生蛋。

所以指针放在用户主目录：`~/.buwang/root.txt`，一行路径。优先级是插件配置 > 指针 > 环境变量 > 默认位置，其中**面板写下的指针压过环境变量**：你在界面上选的才算数。

换位置时只复制、不删除旧目录。搬完发现不对，旧库还在。

## 七、为什么要拦「坏编码的路径」

中文字符路径在跨进程传递时有几种经典坏法：控制台编码把 `D:\备份` 变成一串 `�`，然后它会在磁盘上老老实实建出一个叫 `����` 的文件夹，把整个库搬进去。

所以路径入口有一道检查：含 U+FFFD 就直接拒绝，并说明是编码坏了。宁可失败，也不要在一个看不懂名字的文件夹里留下一份记忆。
